2.4 Tizim chaqiruvi (System Calls)

2.1-darsda ikki dunyo bor edi: imtiyozsiz user space va imtiyozli kernel space. Ular orasidagi yagona qonuniy eshik — tizim chaqiruvi. Faylni o'qish, paket yuborish, protsess yaratish, xotira so'rash — hammasi shu eshikdan o'tadi. Demak bu eshikning kengligi va narxi sizning ilovangizning sig'imini bevosita belgilaydi. Bu darsda uning mexanizmini, narxini va uni kamaytirish usullarini o'rganamiz.

Syscall — funksiya chaqiruvi emas

Kodda read(fd, buf, 4096) oddiy funksiya chaqiruviga o'xshaydi. Aslida bu butunlay boshqacha hodisa. Oddiy funksiya chaqiruvida protsessor shunchaki boshqa manzilga sakraydi. Tizim chaqiruvida esa protsessor imtiyoz darajasini o'zgartiradi:

  • bajarilish ring 3 dan ring 0 ga o'tadi;
  • stek almashtiriladi — yadro o'z stekidan foydalanadi (user stekiga ishonib bo'lmaydi);
  • yadro barcha argumentlarni ishonchsiz deb tekshiradi;
  • qaytishda hamma narsa tiklanadi.

Nega shunchalik murakkab? Chunki bu chegara — xavfsizlik chegarasi. Agar user space kodi yadro funksiyasiga to'g'ridan-to'g'ri sakray olsa, har qanday dastur butun mashinaga egalik qilardi.

Mexanika: read() chaqirilganda nima bo'ladi

Eng past daraja: libc'siz syscall (x86-64, Linux)

; write(1, msg, 13) — assemblyda
mov rax, 1          ; syscall raqami: 1 = write
mov rdi, 1          ; 1-argument: fd = 1 (stdout)
mov rsi, msg        ; 2-argument: bufer manzili
mov rdx, 13         ; 3-argument: uzunlik
syscall             ; ← MANA SHU yerda ring 0 ga o'tiladi
; qaytgach: rax = yozilgan baytlar soni, yoki manfiy xato kodi

; Muhim: xato -errno ko'rinishida qaytadi (masalan -9 = EBADF).
; libc uni musbat errno ga aylantirib, funksiyadan -1 qaytaradi.
Syscall raqamlari — o'zgarmas shartnoma

Linux yadrosining eng qattiq qoidasi: «user space'ni buzmaymiz». Syscall raqamlari va ularning semantikasi hech qachon o'zgarmaydi — shuning uchun 20 yil oldin kompilyatsiya qilingan binary bugungi yadroda ham ishlaydi. Yangi imkoniyat kerak bo'lsa, eski chaqiruv o'zgartirilmaydi, balki yangisi qo'shiladi (open → openat → openat2). Bu — API barqarorligining eng mashhur namunasi.

Narxi: raqamlar bilan

1.1-darsdagi kechikish jadvalining davomi — endi OS darajasida:

AmalTaxminiy narxiNisbat
Oddiy funksiya chaqiruvi~1–2 ns1×

Oddiy syscall (getpid)~50–100 ns~50×
Syscall + Spectre/Meltdown himoyasi~100–300 ns~150×

Ikki xulosa chiqadi. Birinchisi: bitta syscall qimmat emas — 100 ns arzimas. Ikkinchisi: million syscall qimmat — 1 000 000 × 150 ns = 0.15 soniya sof yo'qotish. Shuning uchun optimizatsiya doim bitta savolga qaytadi: chaqiruvlar sonini kamaytirsa bo'ladimi?

Yashirin narx: cache va konveyer

Syscall'ning o'lchangan narxi faqat boshlanishi. Ring almashinuvi konveyerni bo'shatadi, yadro kodi sizning L1/L2 cache'ingizni o'z ma'lumoti bilan almashtiradi, KPTI esa TLB'ni tozalaydi (2.3-dars). Siz qaytganingizda «sovigan» protsessorda ishlaysiz. Bu narx strace da ko'rinmaydi, lekin real tezlikda seziladi.

libc, buferlash va vDSO

Siz deyarli hech qachon syscall'ni bevosita chaqirmaysiz — oradagi libc (glibc, musl) uni qulay funksiyaga o'raydi. Lekin libc shunchaki o'ram emas, u chaqiruvlar sonini kamaytiradi:

printf 1000 marta — lekin syscall bir necha marta

for (int i = 0; i < 1000; i++)
    printf("qator %d\n", i);
// stdout terminalga ulangan bo'lsa — qatorli buferlash (har \n da write)
// faylga yo'naltirilgan bo'lsa  — to'liq buferlash (4 KB to'lganda write)
//   → 1000 ta printf ≈ 3-4 ta write syscall

// Buferlashsiz yozish (har bir chaqiruv = 1 syscall):
write(1, "qator\n", 6);            // to'g'ridan-to'g'ri syscall
setvbuf(stdout, NULL, _IONBF, 0);  // buferlashni o'chirish — sekinlashadi!

// Tekshirib ko'ring:
//   $ strace -c -e trace=write ./dastur > /dev/null

vDSO: syscallsiz syscall

Ba'zi chaqiruvlar shunchalik tez-tez ishlatiladiki (vaqtni olish — har bir log qatorida!), ular uchun yadro maxsus hiyla qo'llaydi: vDSO — yadro har bir protsessning manzil fazosiga kichik kod va ma'lumot sohasini ulab qo'yadi (2.3-darsdagi mapping!). clock_gettime() shu sohadagi soatni ring almashtirmasdan o'qiydi. 

$ cat /proc/self/maps | grep vdso
7ffd3b3f2000-7ffd3b3f4000 r-xp  [vdso]      # har bir protsessda bor

# Shuning uchun bu deyarli tekin:
clock_gettime(CLOCK_MONOTONIC, &ts);   // ~20 ns, syscall YO'Q
# Ammo bu emas:
stat("/etc/hosts", &st);               // ~500 ns, haqiqiy syscall

Syscall sonini kamaytirish: beshta usul

Bu — yuqori unumdorlikli server dasturlarining asosiy mavzusi. Har bir usul bitta g'oyaning turli ko'rinishi: bir marta chaqirib, ko'proq ish qildirish.

1. Buferlash

Eng oddiy va eng samarali. Kichik yozuvlarni to'plab, katta bo'lak qilib yuborish.

// Yomon: 100 000 ta syscall
for (row in rows) write(fd, row, len);

// Yaxshi: ~25 ta syscall (4 MB bufer bilan)
buffer.append(row); if (buffer.size >= 4*1024*1024) { write(fd, buffer); buffer.clear(); }

2. Vektorli I/O (readv / writev)

Bir nechta ajratilgan buferni bitta chaqiruvda yozish — nusxa ko'chirmasdan.

struct iovec iov[3] = {
    { header,  hlen },     // HTTP sarlavhasi
    { body,    blen },     // tana
    { trailer, tlen }
};
writev(fd, iov, 3);        // uchta bufer, BITTA syscall, oraliq nusxa yo'q

3. Zero-copy (sendfile, splice)

Statik faylni tarmoqqa uzatishda ma'lumot odatda to'rt marta ko'chiriladi: disk → page cache → user bufer → soket buferi → NIC. sendfile() esa user space'ni umuman chetlab o'tadi. 

// An'anaviy: 2 syscall + 2 ortiqcha nusxa, har bir bo'lak uchun
while ((n = read(file_fd, buf, 64*1024)) > 0) write(sock_fd, buf, n);

// Zero-copy: bitta syscall, ma'lumot user space'ga umuman chiqmaydi
sendfile(sock_fd, file_fd, NULL, file_size);
// nginx'ning "sendfile on;" sozlamasi aynan shu — statik fayllarda katta farq beradi

4. Ko'p soketni bitta chaqiruvda kuzatish (epoll)

10 000 ta ulanish bo'lsa, har birini alohida so'rash mumkin emas. epoll_wait() bitta chaqiruvda «kim tayyor» degan ro'yxatni qaytaradi — 1.3-darsdagi nginx va Node.js modelining asosi. 

int ep = epoll_create1(0);
epoll_ctl(ep, EPOLL_CTL_ADD, sock, &ev);       // bir marta ro'yxatga qo'shamiz

while (1) {
    int n = epoll_wait(ep, events, 64, -1);    // BITTA syscall
    for (int i = 0; i < n; i++)                // faqat tayyorlari qaytadi
        handle(events[i].data.fd);
}
// Eski select()/poll() esa har safar butun ro'yxatni yadroga uzatardi — O(n).

5. Navbatga asoslangan I/O (io_uring)

Eng zamonaviy yondashuv: user va yadro umumiy xotiradagi ikkita halqali navbat orqali gaplashadi (2.3-darsdagi shared mapping). Siz navbatga «100 ta o'qish» yozib qo'yasiz, yadro bajarib, natijalarni ikkinchi navbatga qo'yadi. Ideal holatda syscall umuman bo'lmaydi.

Naqshni ko'ryapsizmi

Buferlash, writev, sendfile, epoll, io_uring — hammasi bitta g'oyani turli darajada qo'llaydi: chegarani kamroq kesib o'tish va har safar ko'proq ish bajarish. Bu xuddi 1.2-darsdagi «tarmoq so'rovlarini batch qilish» qoidasining bir mashina ichidagi ko'rinishi. Chegara qanchalik qimmat bo'lsa, guruhlash shunchalik foydali.

Xatolar bilan to'g'ri ishlash

Syscall'lar xatoni -1 va errno orqali qaytaradi. Ularning uchtasi xato emas, balki normal holat — va ularni noto'g'ri ishlash eng keng tarqalgan xatolardan biri:

errnoMa'nosiTo'g'ri javob
EINTRchaqiruv signal bilan uzildiqaytadan chaqirish (retry), xato deb hisoblamaslik
EAGAIN / EWOULDBLOCKnon-blocking rejimda hozircha ma'lumot yo'qepoll'ga qaytish va kutish
EMFILE / ENFILEFD limiti tugadilimitni oshirish, FD oqishini qidirish (1.2-dars!)
ENOSPC, EPIPE, ECONNRESEThaqiqiy xatolarishlov berish va jurnalga yozish

Qisman yozish — eng ko'p unutiladigan tafsilot

// XATO: write() hammasini yozdi deb o'ylash
write(fd, buf, len);        // 4096 so'radingiz, 1500 bayt yozilishi mumkin!

// TO'G'RI: qisman yozishni va EINTR'ni hisobga olish
ssize_t written = 0;
while (written < len) {
    ssize_t n = write(fd, buf + written, len - written);
    if (n < 0) {
        if (errno == EINTR) continue;              // signal — qaytadan urinamiz
        if (errno == EAGAIN) { wait_writable(fd); continue; }
        return -1;                                 // haqiqiy xato
    }
    written += n;
}
// Xuddi shu read() uchun ham: qaytgan qiymat so'ralgandan kichik bo'lishi MUMKIN.

Asosiy syscall oilalari

Bu — kurs davomidagi eng amaliy ko'nikmalardan biri. «Dastur sekin» degan noaniq shikoyat strace -c yordamida bir necha soniyada aniq raqamga aylanadi:

strace'ni ehtiyot bilan ishlating

strace ptrace mexanizmiga tayanadi va har bir syscall'ni ikki marta to'xtatadi — dastur 10–100 barobar sekinlashishi mumkin. Yuklangan ishlab chiqarish protsessiga uni ulash — o'zi avariya sababi bo'lishi mumkin. U yerda perf trace yoki eBPF (bpftrace) ishlating.

Syscall yuzasi va xavfsizlik

Syscall interfeysi — user space uchun yadroga yagona kirish nuqtasi. Demak u ayni paytda hujum yuzasi ham: yadrodagi zaiflik odatda qaysidir syscall orqali qo'zg'atiladi. Shuning uchun zamonaviy izolyatsiya bu yuzani toraytiradi:

  • seccomp-bpf — protsessga qaysi syscall'lar ruxsat etilishini belgilaydigan filtr. Docker standart profilida ~44 ta syscall taqiqlangan; ruxsatsizini chaqirish EPERM yoki SIGSYS beradi.
  • Capabilities — root huquqlarini mayda bo'laklarga bo'ladi (CAP_NET_BIND_SERVICE — 1024 dan past portga bog'lanish, CAP_SYS_ADMIN — deyarli hamma narsa).
  • Namespaces + cgroups — 2.3-darsda ko'rganimizdek, ko'rinish va miqdorni cheklaydi.
# Konteynerda syscall taqiqlangani qanday ko'rinadi:
$ docker run alpine mount -t tmpfs none /mnt
mount: permission denied (are you root?)     # seccomp/capability to'sdi

# Aniq nima taqiqlanganini ko'rish:
$ grep Seccomp /proc/self/status
Seccomp: 2                                    # 2 = filtr rejimi yoqilgan
$ capsh --print | head -3
Dizayn nuqtai nazaridan

Ilovangiz qancha kam turdagi syscall ishlatsa, uni shunchalik qattiq qamrab olish mumkin. «Faqat read, write, epoll_wait ishlatadigan» servis uchun juda tor seccomp profili yozish mumkin — bu 1.3-darsdagi «rollarni ajratish» qoidasining xavfsizlikdagi ko'rinishi.

Tez-tez qilinadigan xatolar

  • Kichik bo'laklarni buferlashsiz yozish Har bir write() — rejim almashinuvi; 340 ming chaqiruv sekundlarni yeydi. Buferlang yoki writev ishlating; strace -c bilan tekshiring.
  • write() va read() ning qaytgan qiymatini tekshirmaslik Qisman yozish/o'qish normal holat — ma'lumot jimgina yo'qoladi. Har doim halqa ichida qoldiqni yozing va EINTR ni qayta urining.
  • EAGAIN ni xato deb hisoblash Non-blocking soketda bu «hozircha ma'lumot yo'q» degani xolos. Ulanishni yopmang — epoll ga qaytib, tayyor bo'lishini kuting.
  • Issiq halqada vaqtni ko'p so'rash vDSO tufayli arzon bo'lsa ham, million marta chaqirilsa seziladi (va ba'zi muhitlarda vDSO ishlamaydi). Vaqtni bir marta olib, halqa davomida qayta ishlating.
  • Ishlab chiqarishda strace ni uzoq muddat ulab qo'yish Protsess 10–100 barobar sekinlashadi va bu o'zi avariyaga olib kelishi mumkin. Qisqa namuna oling yoki perf trace / bpftrace ishlating.
  • fsync ni «har ehtimolga qarshi» har yozuvdan keyin chaqirish Bu eng qimmat syscall'lardan biri — sig'imni keskin tushiradi. Guruhlab tasdiqlang (group commit) yoki chidamlilik talabini aniq belgilang (2.1-dars).
  • Konteynerda syscall taqiqini kod xatosi deb qidirish EPERM ko'pincha seccomp yoki capability sababidan keladi. Avval grep Seccomp /proc/self/status va capsh --print bilan tekshiring.

Xulosa

  • Syscall — funksiya chaqiruvi emas, imtiyoz chegarasini kesib o'tish: rejim, stek va ishonch darajasi almashadi.
  • Bitta chaqiruv ~100–300 ns turadi; muammo hech qachon bitta chaqiruvda emas, ularning sonida.
  • libc buferlash bilan chaqiruvlarni kamaytiradi; vDSO esa ba'zi chaqiruvlarni umuman yo'q qiladi.
  • Kamaytirish usullari bitta g'oyaning turli darajalari: buferlash → writev → sendfile → epoll → io_uring.
  • EINTR, EAGAIN va qisman yozish — xato emas, normal holat; ularni to'g'ri ishlash ishonchlilikning asosi.
  • strace -c «dastur sekin» degan shikoyatni bir necha soniyada aniq raqamga aylantiradi; ishlab chiqarishda esa perf/eBPF ishlatiladi.
  • Syscall interfeysi ayni paytda hujum yuzasi — seccomp, capabilities va namespace'lar uni toraytiradi.
